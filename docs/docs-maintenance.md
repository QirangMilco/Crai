# 文档维护检查清单 (Docs Maintenance Checklist)

在更改架构或实现时，请使用此检查清单：

## 编辑前
- 确定更改是否影响架构、API、数据模型、流程或阶段计划
- 首先更新最小的相关文档
- 避免将设计意图和实现细节混为一谈

## 编辑后
- 检查 README 链接是否需要更新
- 验证相关文档在命名上是否保持一致
- 确保新的字段或事件反映在规格文档和流程文档中
- 标记弃用的文档，而不是默默地使其发散

## 建议的更新顺序
1. architecture-overview.md
2. core-api-spec.md
3. data-model.md
4. runtime-flow.md
5. phase-plan.md
6. ../README.md
